# Clash Meta 桌面小组件安装教程（不用完整 Xcode）

更新：2026-09-21。适用预览版：`v1.0.0-preview.1`，App 构建 7。

本工具为已运行的 **ClashX Meta** 提供原生 macOS WidgetKit 桌面小组件。它不是代理内核，也不会自动替你安装 ClashX Meta。

## 先选一种安装方法

| 你希望怎么安装 | 选择 | 需要下载什么 |
| --- | --- | --- |
| 像普通 Mac 软件一样下载使用 | 方法一，直接下载 App | 一个约 435 KB 的 ZIP，无需 Xcode、Command Line Tools、Python 或 Git |
| 自己用公开源码生成 App | 方法二，轻量源码构建 | Apple Command Line Tools 和项目源码；不需要完整 Xcode |

两种方法二选一，不需要都装。下载包和轻量源码构建使用相同实现，功能相同。

使用前确认：Mac 系统至少为 macOS 14；ClashX Meta 已运行。目前只适配应用标识为 `com.metacubex.ClashX.meta` 的客户端，不能保证 Clash Verge、ClashX 普通版或其他“Clash 家族”客户端可用。通用包包含 Apple 芯片和 Intel 两种架构；本轮运行实测是在 Apple 芯片、macOS 26.5.2 上完成。

## 方法一：直接下载 App

### 1. 下载正确的文件

打开 [GitHub 下载页](https://github.com/YL-SSSSu/clash-meta-widget/releases/tag/v1.0.0-preview.1)，展开 **Assets**，下载：

```text
Clash-Meta-Widget-1.0-build7-macos-universal.zip
```

也可点 [ZIP 直接下载](https://github.com/YL-SSSSu/clash-meta-widget/releases/download/v1.0.0-preview.1/Clash-Meta-Widget-1.0-build7-macos-universal.zip)。这里要下载的是带 `macos-universal` 的文件；页面自动生成的 `Source code (zip)` 是源码，不是可直接运行的 App。

### 2. 安装并打开一次

双击 ZIP 解压，得到 `Clash Meta Switch.app`。把它拖到访达的“应用程序”文件夹，再从那里打开。

如果之前装过旧版，先退出旧版 `Clash Meta Switch` 再替换；无需退出正在工作的 ClashX Meta，也不要同时放两份同名小组件应用。

### 3. 处理首次打开提示

此预览版有本地临时签名，但没有 Apple Developer ID 签名和公证。测试中，Gatekeeper 默认评估结果为拒绝，因此普通下载后可能提示“无法验证开发者”等信息。

确认下载来源是上面的项目 Release 后：先尝试打开 App，再进入 **系统设置 → 隐私与安全性**，找到对应的阻止提示；如果有“仍要打开”，点击它并按系统提示确认。这个操作由使用者自己决定，不需要安装 Xcode，也不需要全局关闭 Gatekeeper。苹果的具体说明见 [安全地打开 Mac App](https://support.apple.com/en-gb/102445)。

如果系统报告文件损坏、恶意软件，或没有提供相应确认选项，请先重新下载并检查校验值或向项目反馈，不要把所有安全提示都当作同一种问题。

### 4. 添加桌面卡片

打开 `Clash Meta Switch` 一次，并保持 ClashX Meta 在运行。

1. 在桌面空白处右键，选择“编辑小组件”。
2. 搜索 `Clash Meta` 或 `Clash Meta Switch`。
3. 选择 **中号**，放到桌面。
4. 关闭说明窗口。宿主仍在后台同步状态。

小号只有系统代理开关。旧的小号卡片不会因更新自动变大，右键卡片改成中号即可看到节点与模式按钮。如果系统仍显示旧尺寸，移除旧卡片，再添加中号。

## 方法二：不装完整 Xcode，自己构建

### 1. 安装 Apple Command Line Tools

打开“终端”，运行：

```bash
xcode-select --install
```

按系统弹窗完成安装。这是 Apple 的命令行开发工具包，包含 Swift 编译器和 macOS SDK，不是完整的 Xcode 应用。[Apple 安装说明](https://developer.apple.com/cn/documentation/xcode/installing-the-command-line-tools)

已经安装的用户可以跳过。请使用适合当前 macOS 的较新版本；本次测试的 Swift 版本为 6.3.2，没有逐一验证所有旧版工具链。

### 2. 下载源码并安装

在终端依次运行：

```bash
git clone https://github.com/YL-SSSSu/clash-meta-widget.git
cd clash-meta-widget
bash script/install.sh
```

脚本会使用 `/Library/Developer/CommandLineTools`，构建 Apple 芯片与 Intel 的通用 App，检查签名结构，运行 46 项输入与状态检查，然后安装到“应用程序”并打开。

轻量脚本会为本次构建设置 `DEVELOPER_DIR`，确保编译器、链接和打包工具都来自 Command Line Tools；不会修改电脑全局的 Xcode 选择设置。如果电脑之前删除过 Xcode，而第一条 `git clone` 就报开发目录无效，可在该终端先运行：

```bash
export DEVELOPER_DIR=/Library/Developer/CommandLineTools
```

再重新执行上述命令。

已有同名应用时，安装脚本会把旧版移入废纸篓，文件名带时间，可恢复。若遇到“应用程序”目录没有写入权限，不要反复重试；先完成构建，再用访达把下面的产物拖到“应用程序”，按系统提示处理权限。

只构建、不安装，可运行：

```bash
bash build-lite.sh
```

产物在：

```text
build/lite/Clash Meta Switch.app
```

装好后，按方法一第 4 步添加桌面中号组件。不要为轻量构建运行 `bash build.sh`，那是项目保留的完整 Xcode 构建入口。

## 两种方法装好后，都这样操作

| 中号组件位置 | 操作 |
| --- | --- |
| 右上角电源图标 | 开启或关闭系统代理 |
| 节点名左边、右边的箭头 | 在当前策略组中切换上一个、下一个选项 |
| 底部“规则／全局／直连” | 切换模式 |

节点使用箭头循环选择，当前没有卡片内的任意节点下拉菜单。点击后等卡片状态更新，再继续点。系统决定 WidgetKit 的刷新时刻，连续点击未刷新的旧画面可能收到“已过期”提示。

规则模式按配置分流，全局模式使用 `GLOBAL` 策略组，直连模式不经代理。电源键控制的是系统代理，不是退出内核或关闭 TUN。首次控制 Meta 若出现自动化权限请求，其用途是允许宿主调用 Meta 的开关命令。

### 端口或 API 密钥与默认值不同时

打开 `Clash Meta Switch`，展开“兼容设置”：

| 设置 | 默认值 | 什么时候改 |
| --- | --- | --- |
| 系统代理端口 | `7890` | Meta 的系统代理实际使用了其他端口 |
| 控制接口端口 | `9090` | Meta 的 External Controller 使用了其他端口 |
| 接口密钥 | 留空 | Meta 的控制接口配置了 `secret` |

填写的是现有 Meta 的配置值；这个窗口不会替你修改 Meta 配置。控制地址固定为 `127.0.0.1`，不支持远程控制地址。密钥保存到 macOS 钥匙串，不写进组件快照或仓库。HTTP、HTTPS、SOCKS 使用不同端口的配置不在本次验证范围内。

## 如何判断是否装好

把桌面卡片改成中号后，先记下当前模式和节点。点一次模式按钮，在 ClashX Meta 中核对实际模式；再点一次节点箭头核对节点，最后恢复原选择。不要只看说明窗口出现就认定桌面按钮已经成功。

2026-09-21 的本机测试结果：

- **GitHub ZIP**：重新下载、校验 SHA-256、解压安装，宿主启动正常；节点、三种模式和系统代理开关，经小组件使用的同一 URL 入口均实际生效，并恢复了原设置。
- **Command Line Tools**：干净源码副本构建通过；故意给外层环境设置一个不存在的 Xcode 路径，脚本仍能自行使用 Command Line Tools 完成构建。安装后，相同控制项目全部通过。
- 两种产物都已注册小组件扩展，包含 arm64 和 x86_64；轻量构建的 46 项检查通过。
- **尚未完成**：通过系统桌面卡片实际点击的最终验收；另一台全新 Mac 上的首次 Gatekeeper 确认；Intel 实机和旧版 macOS 的运行测试；带真实 API 密钥或自定义端口的完整联调。

因此目前结论是：**两种安装路线和本机控制功能已验证可用，公开版本仍保留预览版标记。** 更详细的记录见 [测试报告](./TEST_REPORT.md)。

## 可选：核对下载文件

在同一 Release 下载 `SHA256SUMS.txt`，和 ZIP 放在同一目录。例如文件都在“下载”里时，打开终端运行：

```bash
cd "$HOME/Downloads"
shasum -a 256 -c SHA256SUMS.txt
```

看到对应 ZIP 后面显示 `OK` 表示与公布的摘要一致。校验值用于核对文件一致性，不等于 Apple 公证或证明软件没有漏洞。

## 常见问题

- **找不到组件**：确认 App 已放进“应用程序”并打开过一次，再重新打开“编辑小组件”。若仍没有，反馈 macOS 与客户端版本；宿主窗口能打开不代表 WidgetKit 注册一定完成。
- **提示未运行**：先启动 ClashX Meta；工具不自动启动或替换客户端。
- **节点／模式不可用**：检查控制端口和接口密钥；系统代理端口与控制端口是两种用途。
- **系统代理开关被拒绝**：查看系统设置 → 隐私与安全性 → 自动化中对 ClashX Meta 的授权，以及组件提示的其他代理或 PAC/WPAD 冲突。
- **重启后数据不更新**：当前没有登录启动项，打开一次宿主即可恢复后台采样。
- **卸载**：移除桌面卡片，退出宿主，把 `Clash Meta Switch.app` 移到废纸篓。卸载不自动改变当前系统代理；需要关闭代理时请在 Meta 中操作。
