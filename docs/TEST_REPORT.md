日期：2026-09-21。状态：两条路线的本机安装及控制链路通过；桌面点击和全新设备首次安装尚待验证。

## 对象与环境

- 下载对象：GitHub Release `v1.0.0-preview.1` 的 `Clash-Meta-Widget-1.0-build7-macos-universal.zip`。
- ZIP 大小：444,824 字节；SHA-256：`5d3e57126804e6c699960e9b934b51eed6a370c352e26cc175763d0dbfe983ab`。
- 源码对象：公开提交 `28a8401` 的干净导出，加上轻量构建脚本显式设置 `DEVELOPER_DIR` 的修正。
- macOS 26.5.2，Apple 芯片；Command Line Tools 中 Swift 6.3.2，工具路径位于 `/Library/Developer/CommandLineTools`。
- 现有 ClashX Meta；测试使用默认系统代理端口 7890、控制端口 9090，接口未配置密钥。
- 测试机原本装有完整 Xcode；本次没有卸载它，也没有修改全局 `xcode-select`。通过给外层构建环境传入不存在的 Xcode 路径，检查轻量脚本是否仍可完全选择 Command Line Tools。

## 发现并修复的问题

原轻量脚本虽然直接调用 CLT 的 Swift，但 `/usr/bin` 下的 Apple 工具可能仍跟随全局 Xcode 选择。现在先检查 CLT 是否存在，再仅对脚本进程设置 `DEVELOPER_DIR`。修正后的干净构建和安装运行测试通过，全局开发目录保持原样。

本轮没有改 App 控制实现，也没有替换现有 Release ZIP；修正影响源码构建时的工具选择。

## 结论边界

可以确认用户不需要完整 Xcode：可以直接安装预编译 App，也可以使用 CLT 在本机生成 App。两条路线在测试机上的宿主控制功能均通过。

尚不能承诺“任意 Mac 下载即用”或“所有桌面按钮均已通过端到端测试”。带真实 API 密钥、自定义端口、全新设备首次启动、实际桌面点击、旧系统和 Intel 实机应在后续测试中补齐。项目继续使用预览版发布状态。
