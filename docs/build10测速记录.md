# 构建 10：节点延迟显示

日期：2026-09-21。已安装到本机；成品 ZIP 作为 `v1.0.0-preview.2` 发布，使用者不需要 Xcode。

在中号桌面组件点“设置”，节点列表右侧显示连接延迟（ms）。点数值或“测速”测试单项；“测当前列表”测试当前搜索结果，每批最多并发 3 项；“停止”取消尚未完成的任务。绿色低于 200 ms，橙色 200–499 ms，红色为更高延迟或失败。首次打开可显示 Meta 已有记录。

测速使用 Meta 的指定节点延迟接口，固定探测目标为 Google 的 HTTPS 204 页面。它衡量连接响应时间，不衡量下载带宽，不主动切换节点、模式或系统代理。具体 API 与权限边界见 [安全说明](../SECURITY.md)。

## 本机验证

- 通用 Release 构建、代码签名检查及既有 52 项输入与状态检查通过。
- 独立调用应用的测速实现，返回真实延迟，并确认 Selector 选择与模式不变。
- 在真实设置窗口点击节点右侧按钮，显示“测速完成 · 1 项”并更新 ms 数值。
- 搜索筛选后点击“测当前列表”，显示“测速完成 · 8 项”，8 个结果均更新。
- 清空搜索后启动批量测速，再点“停止”，显示“测速已停止”，按钮恢复可用。
- 核对上述 UI 操作前后，全部 Selector 选择、模式及系统代理开关完全一致。
- 已查看实际窗口截图，确认列表右侧数值、进度、批量按钮及窗口底部均可见。
- 旧安装版及构建副本移入废纸篓，只保留应用程序目录中的一份注册。

以上验证的是本机节点窗口测速，不代表已完成所有桌面 WidgetKit 点击或其他机器的兼容验收。测速结果受测试目标、网络与时间影响，不能作为节点带宽或所有站点连通性的保证。
