# “能开不能关”的只读诊断

先收集故障环境，不要反复删除组件，也不要先修改代理端口。

1. 在桌面小组件点击关闭，出现错误后，保持现场，运行 `bash script/diagnose-proxy.sh`，保存输出 A。
2. 在 ClashX Meta 自己的菜单里手动关闭“设置为系统代理”，再次运行相同脚本，保存输出 B。
3. 反馈 A、B 和 ClashX Meta 版本。如果脚本无法读取控制接口，请补充 Meta 界面中的 HTTP、SOCKS、混合及控制接口端口数字。不要发送订阅链接、完整配置文件、接口密钥或私有快照。

脚本无需 Xcode、Python 或管理员权限，不切换代理，不调用 Meta 开关，不读取钥匙串。只向本机控制接口发出一次只读配置请求，不跟随重定向；输出仅包含版本、开关状态和端口。接口需要密钥时会跳过，不要求输入密钥。

脚本默认使用小组件保存的控制接口端口，未设置时为 9090。如果已知 Meta 的控制接口为其他端口，例如 19090，可运行 `bash script/diagnose-proxy.sh 19090`。这只是指定本次检查的地址，不保存或修改设置。

## 如何理解结果

- 构建 10 只有一个系统代理端口设置，并将它用于 HTTP、HTTPS 和 SOCKS 的识别。实际端口与它不同，或 HTTP/SOCKS 分开使用端口，都可能触发误判。
- Meta 的 `mixed-port` 大于 0 时，HTTP 和 SOCKS 优先使用混合端口；为 0 时分别使用 `port` 和 `socks-port`。0 通常表示该监听未启用，不应作为系统代理端口填写。
- 若 A 仍显示开启、B 显示关闭，说明 Meta 能改变系统代理，需要进一步检查小组件的命令执行和状态确认。即使发现端口差异，也应在相同端口配置下复现后才认定根因。
- 若 A 已显示关闭，只是桌面仍显示开启，需要检查 WidgetKit 刷新，而不是修改网络设置。
- 如果控制接口未连接或需要授权，仅凭该结果不能判定代理开关故障。

本机对当前构建 10 的宿主控制入口测试为“关→开→关→开”四次均成功，已恢复原状态；尚未在反馈者环境复现。诊断脚本不等于修复版本。
