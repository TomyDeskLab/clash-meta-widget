# 构建 8：缓存点击与弹窗修复

日期：2026-09-21。状态：本机安装完成，桌面实际点按等待验收；未发布新的下载包。

后续构建 9：按使用需求，在中号小组件增加“⚙ 设置”链接，用于主动打开搜索节点、策略组和模式窗口。其他控制按钮保持静默；小号需右键改为中号才显示此入口。此变化不涉及代理控制逻辑。

## 原因与修改

构建 7 在刷新或执行动作后轮换所有操作凭据，但桌面可能继续显示上一张卡片，导致按钮立即失效。错误路径和应用重新唤起又会打开管理窗口。电脑同时注册了构建目录与应用程序目录的两份同名扩展，增加了版本混淆。

构建 8 保持本地随机凭据稳定。电源按钮每次读取实际系统代理状态再切换；节点箭头按实时选项向前或向后移动；模式按钮设置对应模式。宿主默认后台运行，启动、重开、操作失败均不弹窗。错误留在组件内，只有主动访问设置入口才显示窗口。

这是原生 WidgetKit 桌面卡片，动作仍通过 `Link/widgetURL` 唤起本机宿主，并非 App Intent 后台按钮。系统可能改变焦点。WidgetKit 的刷新由 macOS 调度，界面不保证立即更新，参见 [Apple 刷新机制说明](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date/)。

## 复测结果

- Xcode 通用 Release 构建、签名完整性验证、52 项输入与代理状态检查通过。
- 保存同一个开关链接，实际执行两次，系统代理关闭／开启均生效。
- 保存模式链接，交错执行直连、全局、规则、全局，均从 Meta 接口确认。
- 保存同一个“下一个节点”链接，连续两次均从实际选择继续前进。
- 上述操作没有轮换凭据；伪造链接被拒绝，未改变代理或模式。
- 测试结束恢复原系统代理、模式和所有 Selector 的选择。
- 已安装扩展在运行日志中重新读取到最新快照；文件权限 0600，目录权限 0700。
- 已清理旧程序和测试副本，系统只保留 `/Applications/Clash Meta Switch.app` 的扩展注册。文件移入废纸篓，可恢复；ClashX Meta 本体未改动。

可重复测试入口为 `python3 script/check-cached-actions.py`。它会临时改变真实网络代理状态并恢复，仅用于默认端口、无密钥的本地测试环境，不会自动运行。

**未完成：桌面卡片实际点击最终验收。** 目前桌面自动操作工具持续超时；宿主入口与扩展读取成功不等同于实际桌面点击成功。Command Line Tools 新产物、Intel 实机、新设备首次授权也未完成本轮验收。

## 保留哪一份

本机保留构建 8，不回退构建 6／7，因为旧版仍有单次凭据与缓存卡片冲突。公开 preview.1 下载包还是构建 7，暂不推荐使用。下载成品 App 的使用者不需要 Xcode；本次维护者使用电脑上已有的 Xcode 恢复可运行扩展，没有要求使用者重新下载它。

旧卡片若仍使用已撤销链接，移除后重新添加一次。中号提供开关、节点箭头与三种模式，小号只有开关。需要兼容设置时，主动运行 `open 'clash-meta-switch://settings'`。

## 安全取舍

可重复使用的随机凭据兼容桌面缓存，但不再提供防重放保证。同一用户下能够读取私有快照的恶意程序可重复调用；不要分享快照或完整动作 URL。模式和节点仍受白名单、实时校验及固定本机地址限制。详见 [安全说明](../SECURITY.md)。这些检查不代表不存在漏洞。
